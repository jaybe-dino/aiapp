# 진단 · 개선방향 · 설계 보강 (자료 → 서비스)

두 입력 자료(`시스템 개발 기획안`, `UX 서비스 기획안`)를 바탕으로 부족한 점·오류·개선방향을 정리하고,
이 저장소의 MVP가 그 간극을 어떻게 메웠는지 매핑한 문서입니다.

---

## 1. 자료 총평

기획 자체는 **프로덕션 수준**입니다. 특히 다음은 그대로 계승했습니다.
- **Answer-First 광고독립성** — 답변 확정 전 오퍼 조회 금지(불변조건 1)
- **불변 복식부기 원장** — 잔액 컬럼 없이 균형 분개로만 금액 생성
- **멱등성 도처** — 클릭·전환·원장·쿠폰
- **목적별 동의 분리**, 고위험 광고 차단, 전환별 경제효과 1회

## 2. 핵심 간극 (부족/오류)

### 🔴 G1. 정체성/범위 불일치 — 가장 큰 이슈
- 자료: **55~69세 시니어 생활비서 AI + 제휴 오퍼**
- 사용자 최종그림: **쇼핑+오퍼월+캐시워크+광고로 돈버는 대중 리워드 앱**
- 자료의 "시니어 저밀도 UX(한 화면 한 행동)"과 대중 리워드 앱의 고밀도/게임화는 충돌.
- **개선방향(채택):** *하이브리드 대중 리워드*. 자료의 3대 자산(광고독립 AI·투명 원장·목적동의)을 **차별점**으로 유지하되, 대중 리워드 앱의 4대 수익 루프를 하나의 원장으로 통합.

### 🔴 G2. 캐시워크(걷기 리워드)가 두 자료에 전무
- 사용자가 핵심으로 꼽은 걷기/잠금화면 광고가 **한 줄도 없음**.
- **원칙 충돌:** 자료는 "대화·체류에 현금 지급 금지"인데, 걷기 리워드는 자칫 "행위 자체 보상"이 됨.
- **개선방향(채택 & 구현):** 걷기 보상을 **"걸음 마일스톤에서 광고를 시청하면 지급"**으로 재정의. 재원은 잠금화면/리워드 광고 CPM(자체 광고망 전환). → `src/modules/cashwalk`.

### 🟠 G3. 오퍼월/공급사 실연동 규격 부족
- Buzzvil·NBT·AdPOPcorn·쿠팡파트너스가 표로만 언급, SDK·S2S postback 서명 시퀀스 미정의.
- 리워드 트래픽 승인 여부가 오퍼 노출/보상 가부를 좌우하는데 데이터모델에 약함.
- **개선(구현):** `suppliers.reward_traffic_allowed`로 강제. 미승인 공급사(예: 쿠팡파트너스)는 후보에서 자동 제외. postback 어댑터 엔드포인트 `POST /v1/suppliers/:supplier/postbacks` 구현.

### 🟠 G4. 유닛 이코노믹스 공백
- 리워드 앱 ARPU는 낮은데 유저당 LLM 비용은 큼 → 무제한 AI 제공 시 적자 위험.
- eCPM·전환율·환급률 가정치가 자료에 없음.
- **개선(부분 구현 + 로드맵):** 원장에 `commission_revenue`/`reward_expense`를 분리 기록해 **거래별 마진(수수료−보상)**을 항상 계산 가능하게 함. AI 비용 게이팅(등급 라우팅·캐시)은 `provider.ts` 등급 추상화로 훅 마련. → §4 참조.

### 🟠 G5. 규제 공백
- 자료는 개인정보/AI기본법은 다루나 다음이 빠짐:
  - **위치정보법** — 걸음/위치 데이터 사용 시 위치정보사업자 신고 이슈. (→ 걷기는 걸음수만 쓰고 위치는 수집 안 하도록 설계)
  - **전자금융거래법** — 포인트/쿠폰의 선불전자지급수단 해당 여부.
  - **통신판매중개** — 제휴 커머스 중개자 지위 고지.
  - **사행성/경품** — 랜덤 보상·룰렛류 도입 시.
- **개선방향:** §5 규제 체크리스트로 정리(법률 검토 선행 항목).

### 🟡 G6. 산출물이 전부 문서 (실행 코드 없음)
- **개선(구현):** 이 저장소 = 구동되는 MVP 스캐폴드. 돈버는 루프 전체를 코드로.

### 🟡 소소한 오류
- 문서가 참조하는 `final_report.md`, `product_business_model.md` 미첨부.
- (자료 QA에 이미 기록된) 15.6절 번호 교정 — 반영됨.

| 간극 | 이 MVP의 대응 | 위치 |
|---|---|---|

## 4. 4대 수익 루프와 원장 통합

```
쇼핑(CPS)     클릭→구매 postback→전환 귀속→pending→approved→available
오퍼월(CPA)   미션 참여→완료 postback→전환 귀속→pending→...→available
걷기(CPM)     걸음 마일스톤→광고시청→자체광고망 전환→즉시 available
AI 추천광고   답변 확정 후 관련 오퍼 카드 1개(광고독립)→클릭→위 CPS/CPA로 합류
                              │
                              ▼
                   ★ 단일 불변 복식부기 원장 ★
       (거래별 수수료 수익 − 보상 비용 = 마진, 항상 균형 유지)
```

유닛 이코노믹스 검증 가설(자료 15장 KPI 확장):
- 거래별 `commission_revenue − reward_expense > 0` 경로 실측
- 유저당 LLM 비용 ≤ 유저당 순마진이 되도록 AI 사용량 게이팅(캐시·등급 라우팅·일일 무료한도)

## 5. 규제 체크리스트 (법률 검토 선행)

| 영역 | 확인 포인트 | 이 MVP의 보수적 기본값 |
|---|---|---|
| 위치정보법 | 걸음/위치 수집 시 사업자 신고 | **위치 미수집**, 걸음수만 사용 |
| 전자금융거래법 | 포인트/쿠폰의 선불수단 해당성 | 현금출금 제외, 모바일 쿠폰만 |
| 통신판매중개 | 중개자 지위·책임 고지 | 오퍼 카드에 광고주·조건 고정 노출 |
| 개인정보(생성형AI) | 목적별 동의, 최소수집 | 대화원문 광고망 미전달, 제한 의도문맥만 |
| 광고심의/표시광고 | 고위험·과장 광고 | 대출/투자/의약품/도박 자동추천 제외 |
| 청소년보호 | 연령 확인 | (로드맵) 연령 게이트 |
| 사행성 | 랜덤보상 도입 시 | MVP 미도입 |

## 6. 다음 단계 로드맵 (MVP 이후)

1. **인증/보안**: 실 로그인, mTLS·HMAC postback 강제, 필드 암호화, 강한 인증 결제.
2. **비동기화**: Outbox + 큐로 전환 처리/쿠폰 발급/알림 분리(현재 동기).
3. **RAG·평가셋**: 검수 지식 + 오프라인 평가 게이트(광고독립·출처정확성 최소통과선).
4. **어뷰징 고도화**: 기기무결성(SafetyNet/DeviceCheck), GPS/센서 조작 탐지, 다계정.
5. **운영 콘솔**: 오퍼 승인 이중결재, 대사 자동화, 개인정보 요청 처리.
6. **정산·대사**: 공급사 리포트 vs 원장 일일 대조, 차이 시 지급 보류.
7. **현금성 지급**: 실명확인·세무·전자금융 검토 후 단계 도입.
