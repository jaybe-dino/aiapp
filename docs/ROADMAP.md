# 혜택AI 추가 개발 백로그 (Roadmap)

MVP 스캐폴드 이후 **추후 넣을 기능**을 영역별로 정리한 문서입니다.
우선순위: **P0** = 실서비스 출시 전 필수 · **P1** = 초기 운영 중 · **P2** = 확장.
난이도(대략): S(작음) / M(중간) / L(큼).

> 현재까지 구현됨: Answer-First AI(mock/Claude) · 쇼핑/오퍼월/**렌탈** 오퍼 · 전환귀속 · 불변 보상원장 ·
> 쿠폰 지급 Saga · 캐시워크(걷기) · 운영자 콘솔(이중승인·대사) · iOS/Android 앱 · 웹 · 웜 디자인.
> 인증은 `x-user-id` 헤더 스텁, DB는 SQLite, 광고/제휴는 시뮬레이션 상태.

원장 불균형 · 보상 중복/소실 · 광고 독립성 위반 · 고위험 광고 노출 · 동의 철회 실패 ·
핵심 접근성 실패 · 개인정보 목적외 처리. (이 기준을 P0 항목들이 실제 데이터로 만족해야 함)

## 1. 렌탈 서비스 고도화 ⭐ (사용자 우선 요청)

현재: 정수기·비데·공기청정기 렌탈 오퍼가 커머스→전환→원장 루프에 연결됨(시뮬레이션).
실서비스로 만들려면 렌탈 특유의 **리드/설치 확정/장기 승인/정기결제** 특성을 반영해야 함.

| 항목 | 내용 | 우선/난이도 |
|---|---|---|
| 실 제휴사 연동 | 코웨이·교원웰스·SK매직·청호나이스·LG 등 CPA/리드 API·정산조건 **서면 계약** | P0 / L |
| 리드 수집 폼 | 이름·연락처·설치주소·희망 상담시간 → **제3자 제공 별도 동의 화면**(제공 회사·항목·목적·보유기간 명시) | P0 / M |
| 상담·설치 상태 추적 | 신청 → 상담예약(콜백) → 설치확정 → 보상 **타임라인**(장기 승인 45일+ 대응) | P1 / M |
| 렌탈료 시뮬레이터 | 약정(36/48/60개월)별 월요금·**총 소유비용**·중도해지 위약금 계산기 | P1 / M |
| 렌탈 상세 화면 | 모델 스펙·필터 교체주기·방문/자가관리 선택·사은품·설치비 | P1 / M |
| 동일품목 비교 | 여러 제휴사 같은 품목을 **사용자 순가치**(월요금+위약금 위험)로 비교, 1개 추천 | P2 / M |
| 카테고리 확장 | 안마의자·매트리스·연수기·에어컨·전기레인지 등 구독형 확대 | P2 / M |
| 장기 전환/부분취소 | 설치확정→유지확인 기반 승인, **초기 해지 환수**(부분 reversal) 원장 처리 | P0 / M |
| 렌탈 특화 어뷰징 | 허위 설치·자가계약·중복 리드 탐지 규칙 | P1 / M |

## 2. 인증 · 계정 · 보안 (실서비스 선행 필수)

| 항목 | 내용 | 우선/난이도 | 상태 |
|---|---|---|---|
| 세션 인증 | 게스트/휴대폰OTP 로그인, HMAC 서명 세션 토큰(Bearer), /v1/me | P0 / L | ✅ 1차 구현 |
| 목적별 동의 강제 | 렌탈 리드 등 제3자 제공 오퍼는 third_party 동의 없으면 403 | P0 / M | ✅ 구현 |
| postback 서명 검증 | 공급사 시크릿으로 raw body HMAC(X-Signature) 검증, 실패 401 | P0 / M | ✅ 구현 |
| 쓰기 레이트리밋·보안헤더 | 분당 상한(429), nosniff/DENY 등 | P0 / S | ✅ 1차 구현 |
| 실 본인인증 연동 | PASS 본인확인, 카카오/애플 소셜 로그인(현재 OTP 스텁) | P0 / L | ⬜ |
| 결제·교환 강한 인증 | 쿠폰 교환·리드 제출 시 생체/PIN 재확인 | P0 / M | ⬜ |
| mTLS·IP allowlist | postback에 HMAC 외 mTLS/IP 제한 추가 | P1 / M | ⬜ |
| 필드 암호화 | 연락처·주소 등 민감필드 KMS 암호화, 비밀관리 | P0 / M | ⬜ |
| 로그 PII 마스킹 | 토큰·연락처·대화 민감정보 로그 제외 | P0 / S | ⬜ |
| 운영자 보안 | SSO/MFA, 세분 RBAC, 세션 정책(현재 토큰 스텁) | P1 / M | ⬜ |

> 레이트리밋은 현재 인메모리(단일 인스턴스) → 다중 인스턴스 시 Redis 기반으로 교체 필요.

## 추천 진행 순서(초기 파일럿까지)

1. **P0 법무·보안 기반** — 실 로그인, 동의/개인정보, 전자금융·위치정보 검토, postback 보안
2. **P0 실연동 1종씩** — 오퍼월 1곳 + 렌탈 1곳 + 잠금화면 광고 1곳 서면계약·SDK
3. **P0 인프라** — PostgreSQL·배포·대사 자동화
4. **P1 렌탈 고도화·AI/RAG·푸시·어뷰징** — 파일럿 지표 보며 확장
5. **P2 현금출금·비교·카테고리 확장·ML 사기탐지**

> 상세 배경·규제 진단은 [`GAP_ANALYSIS.md`](GAP_ANALYSIS.md), 시스템 설계는 `docs/source/system_dev_plan_final.md` 참고.
