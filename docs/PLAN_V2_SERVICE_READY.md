# 혜택AI — 서비스 가능 수준 기획 고도화 (v2)

4개 역할(기획자·PM·QA·디자이너)이 실제 코드를 감사하고, 아래 교차 라운드로 런칭 컷라인을
합의했다. 각 지적은 실제 파일·라인 근거를 가진다.

## 감사 요약(역할별 Top)

| 역할 | 핵심 지적 |
|---|---|
| **기획자** | "돈이 실제로 도는가"가 시뮬레이션(광고 CPM 상수·오퍼 7개·pending 수동승인). 시니어 핵심(음성·글자크기·설정·동의철회 UI)이 데이터 모델에만 있고 화면에 없음. 리텐션 루프(푸시·출석) 부재. |
| **PM** | 인증 없는 관리자 보상 엔드포인트(도난경로). 걷기 CPM 재원 미검증(순손실). 쿠폰 공급사 mock. KPI 계측 전무. 런칭 컷라인 정의 필요. |
| **QA** | 포스트백 `cashwalk_ad` 사칭 → 임의 즉시지급(치명). 운영 비밀 dev 기본값 폴백(치명). 전환 귀속이 만료·공급사·서명 미검증(치명). 지급 saga 비원자성. 머니경로 테스트 공백. |
| **디자이너** | P/원 단위 혼용(신뢰 훼손). `muted` 대비 3.4:1 AA 미달. 결제·개인정보 고지가 다단계 Alert. 음성 약속 vs STT 없음. 웹 ⚠️ 항상 렌더 버그. |

## 교차 라운드 (역할 간 상호작용 로그)

**R1 — QA→전체(치명 3종 제기):** QA가 포스트백 `cashwalk_ad` 사칭·dev 비밀 폴백·귀속 미검증을 "런칭 차단"으로 올림.
→ **PM 수용:** "인증 없는 admin 보상 엔드포인트(routes.ts:296)도 같은 계열. 넷 다 D0 이전 필수." 컷라인 1군으로 확정.

**R2 — 기획자↔PM(수익 재원 논쟁):** 기획자 "걷기 CPM이 상수라 순손실, 오퍼 7개라 커머스 가치 붕괴 — 이게 더 근본."
→ **PM 반론·조정:** "재원 실연동(SDK·계약)은 리드타임이 길어 D0 차단으로 두면 런칭이 무기한. **대안: 걷기 탭을 '준비중'으로 내리고 대화+혜택+쿠폰으로 축소 런칭**하되, 순손실 구조(즉시 available)는 코드에서 막는다." → 합의: 재원은 '축소 런칭'으로 우회, 단 **즉시지급 사칭 경로는 코드로 차단**(R1과 결합).

**R3 — QA↔PM(테스트 vs 속도):** QA "머니경로 테스트가 0이라 보안 수정의 회귀를 못 잡는다."
→ **PM:** "치명 수정분에 한해 통합 테스트를 붙이는 조건으로 머지." → **QA 수용.** 보안 픽스마다 재현 테스트 1개 이상.

**R4 — 디자이너↔기획자(단위·신뢰):** 디자이너 "P/원 혼용은 시니어 신뢰의 근본. 돈 앱에서 치명."
→ **기획자 동의·격상:** "포인트 경제 설계(적립↔사용)와 함께 **단위를 '원'으로 통일**, 1P=1원 등가는 온보딩 1회 고지." 퀵윈이라 D0 포함.

**R5 — 디자이너↔QA(고지 전달):** 디자이너 "결제·개인정보 고지가 회색 저대비 다단계 Alert라 이해 불가."
→ **QA 결합:** "고지 미이해는 PIPA 동의 유효성 리스크와 직결. 대비 상향은 D0, 바텀시트 전환은 D0+1스프린트." → 합의.

**R6 — PM 종합(컷라인 확정):** 위를 종합해 D0 Go 조건과 다음 스프린트를 아래로 확정. 기획자·QA·디자이너 사인오프.

## 런칭 컷라인 (합의 결과)

### ✅ D0 필수 (Go 조건) — 이번 개발 반영分
1. **인증/게이팅 구멍 봉인** — admin 보상 엔드포인트를 인증+dev게이트로. (QA·PM)
2. **포스트백 `cashwalk_ad` 사칭 차단** — 외부 포스트백에서 걷기 보상 즉시지급 금지, 내부 경로만 허용. (QA#1)
3. **전환 귀속 검증** — 클릭 만료·공급사 일치 확인, 불일치 시 review. (QA#3)
4. **운영 비밀 fail-fast** — prod에서 dev 기본 비밀이면 기동 실패. (QA#2)
5. **금전 단위 '원' 통일** — P/원 혼용 제거. (디자이너#1)
6. **고지 가독성** — `muted` 대비 AA↑, 중요 고지 muted 금지. (디자이너#2)
7. **웹 불확실성 경고 버그** — 메시지 있을 때만 ⚠️ 렌더. (디자이너#6)
8. **보상 단위·상품 정합** — payout product/amount 매핑. (기획자G7·디자이너#1)
9. **머니경로 보안 테스트** — 위 2·3 재현 테스트. (QA#3 라운드 합의)

### ⏭️ 다음 스프린트 (D0+)
- 광고 SDK+SSV 실연동 / 쿠폰 공급사 계약·비동기화 / 오퍼 피드 파이프라인 (기획자·PM: 재원·커버리지)
- 설정 탭(글자크기·음성·동의철회·계정) + 음성 STT/TTS + 온보딩(약관·처리방침·연령) (기획자G4·G5)
- KPI 이벤트 계측 테이블 + answers에 need_level/reward_nudge 컬럼 (PM#4)
- 지급 saga 원자성·reverse 원장 회수·approve≤expected 가드 (QA#4·5·6)
- 휴대폰 OTP 실발송·1연락처1계정·기기무결성 서버검증 (PM#5·QA#7·8)
- PIPA 보관기간·삭제/열람권·복호화 감사로그 (QA#9)
- 고지 바텀시트 전환·접근성 시맨틱·리텐션(푸시·출석·백그라운드 걸음) (디자이너#3·8, 기획자G6)

### 🟢 유지(재작업 불필요, 차별점)
불변 복식부기 원장, 쿠폰 Saga UNKNOWN 복구, Answer-First 광고독립, 이중승인 governance,
포스트백 HMAC 검증, 니즈 게이팅+2단계 LLM 큐레이션 — 설계 골격은 프로덕션급.

## 한 줄 결론
설계 골격은 런칭 가능 수준이나 "돈이 들어오고 나가는 경계"와 "출시 안전장치"가 시뮬레이션이었다.
이번엔 **코드로 막을 수 있는 치명 보안·정합·신뢰 항목(D0 1~9)을 실제 반영**하고, 재원·규제·리텐션은
축소 런칭 + 다음 스프린트로 컷라인을 명확히 했다.
