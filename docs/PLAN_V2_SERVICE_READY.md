# 혜택AI — 서비스 가능 수준 기획 고도화 (v2)

4개 역할(기획자·PM·QA·디자이너)이 실제 코드를 감사하고, 아래 교차 라운드로 런칭 컷라인을
합의했다. 각 지적은 실제 파일·라인 근거를 가진다.

## 감사 요약(역할별 Top)

| 역할 | 핵심 지적 |
|---|---|
| **기획자** | "돈이 실제로 도는가"가 시뮬레이션(광고 CPM 상수·오퍼 7개·pending 수동승인). 시니어 핵심(음성·글자크기·설정·동의철회 UI)이 데이터 모델에만 있고 화면에 없음. 리텐션 루프(푸시·출석) 부재. |
| **PM** | 인증 없는 관리자 보상 엔드포인트(도난경로). 걷기 CPM 재원 미검증(순손실). 쿠폰 공급사 mock. KPI 계측 전무. 런칭 컷라인 정의 필요. |
| **QA** | 포스트백 `cashwalk_ad` 사칭 → 임의 즉시지급(치명). 운영 비밀 dev 기본값 폴백(치명). 전환 귀속이 만료·공급사·서명 미검증(치명). 지급 saga 비원자성. 머니경로 테스트 공백. |
| **디자이너** | P/원 단위 혼용(신뢰 훼손). `muted` 대비 3.4:1 AA 미달. 결제·개인정보 고지가 다단계 Alert. 음성 약속 vs STT 없음. 웹 ⚠️ 항상 렌더 버그. |

## 교차 라운드 (역할 간 상호작용 로그)

**R1 — QA→전체(치명 3종 제기):** QA가 포스트백 `cashwalk_ad` 사칭·dev 비밀 폴백·귀속 미검증을 "런칭 차단"으로 올림.
→ **PM 수용:** "인증 없는 admin 보상 엔드포인트(routes.ts:296)도 같은 계열. 넷 다 D0 이전 필수." 컷라인 1군으로 확정.

**R2 — 기획자↔PM(수익 재원 논쟁):** 기획자 "걷기 CPM이 상수라 순손실, 오퍼 7개라 커머스 가치 붕괴 — 이게 더 근본."
→ **PM 반론·조정:** "재원 실연동(SDK·계약)은 리드타임이 길어 D0 차단으로 두면 런칭이 무기한. **대안: 걷기 탭을 '준비중'으로 내리고 대화+혜택+쿠폰으로 축소 런칭**하되, 순손실 구조(즉시 available)는 코드에서 막는다." → 합의: 재원은 '축소 런칭'으로 우회, 단 **즉시지급 사칭 경로는 코드로 차단**(R1과 결합).

**R3 — QA↔PM(테스트 vs 속도):** QA "머니경로 테스트가 0이라 보안 수정의 회귀를 못 잡는다."
→ **PM:** "치명 수정분에 한해 통합 테스트를 붙이는 조건으로 머지." → **QA 수용.** 보안 픽스마다 재현 테스트 1개 이상.

**R4 — 디자이너↔기획자(단위·신뢰):** 디자이너 "P/원 혼용은 시니어 신뢰의 근본. 돈 앱에서 치명."
→ **기획자 동의·격상:** "포인트 경제 설계(적립↔사용)와 함께 **단위를 '원'으로 통일**, 1P=1원 등가는 온보딩 1회 고지." 퀵윈이라 D0 포함.

**R5 — 디자이너↔QA(고지 전달):** 디자이너 "결제·개인정보 고지가 회색 저대비 다단계 Alert라 이해 불가."
→ **QA 결합:** "고지 미이해는 PIPA 동의 유효성 리스크와 직결. 대비 상향은 D0, 바텀시트 전환은 D0+1스프린트." → 합의.

**R6 — PM 종합(컷라인 확정):** 위를 종합해 D0 Go 조건과 다음 스프린트를 아래로 확정. 기획자·QA·디자이너 사인오프.

## 런칭 컷라인 (합의 결과)

### ✅ D0 필수 (Go 조건) — 이번 개발 반영分
1. **인증/게이팅 구멍 봉인** — admin 보상 엔드포인트를 인증+dev게이트로. (QA·PM)
2. **포스트백 `cashwalk_ad` 사칭 차단** — 외부 포스트백에서 걷기 보상 즉시지급 금지, 내부 경로만 허용. (QA#1)
3. **전환 귀속 검증** — 클릭 만료·공급사 일치 확인, 불일치 시 review. (QA#3)
4. **운영 비밀 fail-fast** — prod에서 dev 기본 비밀이면 기동 실패. (QA#2)
5. **금전 단위 '원' 통일** — P/원 혼용 제거. (디자이너#1)
6. **고지 가독성** — `muted` 대비 AA↑, 중요 고지 muted 금지. (디자이너#2)
7. **웹 불확실성 경고 버그** — 메시지 있을 때만 ⚠️ 렌더. (디자이너#6)
8. **보상 단위·상품 정합** — payout product/amount 매핑. (기획자G7·디자이너#1)
9. **머니경로 보안 테스트** — 위 2·3 재현 테스트. (QA#3 라운드 합의)

### ⏭️ 다음 스프린트 (D0+)
- 광고 SDK+SSV 실연동 / 쿠폰 공급사 계약·비동기화 / 오퍼 피드 파이프라인 (기획자·PM: 재원·커버리지)
- 설정 탭(글자크기·음성·동의철회·계정) + 음성 STT/TTS + 온보딩(약관·처리방침·연령) (기획자G4·G5)
- KPI 이벤트 계측 테이블 + answers에 need_level/reward_nudge 컬럼 (PM#4)
- 지급 saga 원자성·reverse 원장 회수·approve≤expected 가드 (QA#4·5·6)
- 휴대폰 OTP 실발송·1연락처1계정·기기무결성 서버검증 (PM#5·QA#7·8)
- PIPA 보관기간·삭제/열람권·복호화 감사로그 (QA#9)
- 고지 바텀시트 전환·접근성 시맨틱·리텐션(푸시·출석·백그라운드 걸음) (디자이너#3·8, 기획자G6)

### 🟢 유지(재작업 불필요, 차별점)
불변 복식부기 원장, 쿠폰 Saga UNKNOWN 복구, Answer-First 광고독립, 이중승인 governance,
포스트백 HMAC 검증, 니즈 게이팅+2단계 LLM 큐레이션 — 설계 골격은 프로덕션급.

## 한 줄 결론
설계 골격은 런칭 가능 수준이나 "돈이 들어오고 나가는 경계"와 "출시 안전장치"가 시뮬레이션이었다.
이번엔 **코드로 막을 수 있는 치명 보안·정합·신뢰 항목(D0 1~9)을 실제 반영**하고, 재원·규제·리텐션은
축소 런칭 + 다음 스프린트로 컷라인을 명확히 했다.

## v2.1 — 50~70대 사용자 온보딩·신뢰 (PM·기획자 라운드)

50~70대 첫 사용자의 최대 장벽은 **① 사기 의심(신뢰) ② 개념 생소함(이해)**.

라운드: 기획자(신뢰가 1순위, 수익구조 투명 공개) → PM(온보딩 3스텝·건너뛰기·즉시 가치)
→ 기획자(포인트/확인중/쿠폰 개념 FAQ 필수) → PM(신뢰 지표 일관 노출) → 합의.

반영(모바일·웹 동일):
- **첫 실행 온보딩 3스텝**: 물어보기 → 필요할 때만 혜택 → 걷고 참여해 포인트.
  각 스텝에 신뢰 문구(광고 무관·필요없으면 안 봐도 됨·위치 미수집/동의 시에만 전달). 건너뛰기 허용.
- **도움말(FAQ)**: 포인트 받는 법·‘확인 중’ 의미·안전/비용·광고 필수 여부·쿠폰 사용.
- **앱 소개 다시 보기**(설정) — 온보딩 재열람.
- 큰 글씨: OS 글자확대 존중(allowFontScaling 유지). 인앱 배율 토글은 다음 단계.

## v2.2 — 범용 AI 어시스턴트 재정의 + 가드레일 고도화 (50~70대)

핵심 재정의: 기본 서비스는 **Manus/Claude 같은 범용 AI 어시스턴트**이고, 혜택·포인트는 그 위의 부가 레이어.
따라서 **답변 안전성(가드레일)이 1순위**. 50~70대는 사기·건강·금융 위험 노출이 크다.

가드레일 엔진(safety.ts) 재작성:
- 카테고리 감지: **사기(scam)·위기(crisis)·건강(health)·금융(finance)·법률(legal)**.
  사기·위기는 critical(강경), 건강·금융은 warn, 법률은 info.
- 위험 감지 시 ① 광고 미노출 ② 사용자 안전 안내 카드(전화 연결: 112/1332/1393/1577-0199)
  ③ LLM 시스템 프롬프트에 카테고리별 안전 지침 주입(안전하게 답하도록 유도).
- 사기 최우선: '원금 보장·고수익', '수수료 먼저', '인증번호/계좌 요구', 기관·가족 사칭 등 패턴.
- 회귀 테스트(test/safety.test.ts) 5종. 전체 24개 통과.

UX 단순·친근화:
- AI 홈을 어시스턴트 우선으로 정리: 지갑 강조 제거, "생활·건강·돈 무엇이든" 카피,
  정직한 입력 유도(가짜 마이크 → ✏️), 예시에 사기 점검 프롬프트 추가.
- 안전 안내 카드를 답변 바로 아래 눈에 띄게(critical=적색·전화버튼). 모바일·웹 동일.

효과(실측): "원금 보장·고수익, 수수료 먼저 송금" 질문에 실제 LLM이
"그것은 사기입니다. 절대 송금하지 마세요" + 사기 이유·대응 단계 + "당신은 속은 게 아니라
똑똑하게 멈춘 것"이라는 정서적 지지까지 생성, 광고는 미노출.

## v2.3 — 가드레일 확장·관리 + 답변 품질 + 큰 글씨

가드레일 확장:
- 입력: 개인정보(PII) 감지·마스킹 — 주민번호·카드·계좌 입력 시 자동으로 가려 저장(원문 평문 미보관) + 안내.
- 카테고리 추가: 성인·선정(adult). 출력 스크리닝: 답변에 위험 내용(송금 유도·자해 방법 등) 새어 나오면 안전 문구로 대체(심층 방어).
- 운영 관리: guardrail_rules 테이블로 카테고리 활성화·안내문을 콘솔에서 조정(패턴은 코드).

가드레일 관리 콘솔(어드민 '가드레일' 탭):
- 6개 카테고리 켜기/끄기 + 안내 제목·내용 편집·저장(감사 로그 기록).
- PII 마스킹 감지 수, 카테고리별 최근 감지 통계, 최근 안전 감지 목록.
- 이벤트(safety_flag)로 관측 → 오탐 튜닝 근거.

답변 품질(범용 어시스턴트):
- 후속 질문 유도(follow_ups): 답변 아래 "이어서 물어보기" 칩. 탭하면 대화 이어감(위기·사기 상황엔 미노출).

접근성:
- AI 대화 글자 크기 3단계(보통·크게·아주 크게), 설정에서 조정·저장. 시니어 가독성.

검증: 백엔드/모바일 typecheck, 테스트 24개 통과. 어드민 가드레일 콘솔·후속질문·PII 마스킹 스크린샷 확인.

## v2.4 — P1 AI 품질: 멀티턴 대화 기억 + 일일 상한

- **멀티턴 대화 기억**: 같은 대화의 이전 턴(user/assistant)을 LLM에 함께 전달(최근 6턴, 토큰 방어).
  후속 질문("그럼 비데는?")이 이전 맥락(렌탈·생활비)을 이어받아 자연스럽게 답함. 클라이언트는
  이미 conversationId를 보내므로 무변경으로 적용. answers 테이블을 대화 이력으로 재사용.
- **일일 대화 상한**(DAILY_CHAT_CAP, 기본 200): 초과 시 LLM 호출 없이 안내 반환(비용·어뷰징 방어).
- 테스트: test/memory.test.ts(이력 복원·최근 N턴 제한·상한 안내) 3종. 전체 27개 통과.
- E2E(npm run e2e)에 맥락 의존 질문 턴 추가로 기억 동작 시연.

남은 P1: 스트리밍 응답(구조화 JSON 계약과 병행 설계 필요), 리텐션(푸시·출석·홈 요약).

## v2.5 — 지속형 동반자: 선제 대화(오늘의 이야기) + 위치 맥락

핵심 재정의: 일회성 Q&A → **매일 안부를 건네는 관계형 동반자**(리텐션 엔진). "위치부터".

- **선제 대화 엔진**(proactive.ts): 시간대·위치(날씨)·걷기·보상 맥락을 모아 따뜻한 안부 +
  탭하면 대화가 시작되는 주제 + 걷기/보상 바로가기를 생성. GET /v1/proactive.
- **위치 맥락**: 동네(시/구)만 저장(정밀 좌표 X), location 동의가 있을 때만 날씨 사용(프라이버시).
  설정에 '내 동네' + 위치 동의. 날씨는 어댑터(weather.ts, 샘플→기상청 교체 가능).
- **오늘의 이야기 카드**: AI 홈 최상단에 앱이 먼저 건네는 안부 카드(모바일·웹). 멀티턴 기억과 연결.
- 검증: 동네=서울 마포구 설정 시 "미세먼지 많음 17°" 맥락 메시지·주제 카드 렌더 확인.

다음(리텐션 완성): **푸시 알림 + 스케줄러** — 앱이 꺼져 있어도 하루 1~2회 선제 안부를 보낸다.
  · Expo push 토큰 등록 + 서버 크론(아침 안부·걷기 독려·보상 안내) · 사용자별 발송 시간/빈도 설정 · 조용시간.
  · 알림 → 탭 → 오늘의 이야기 대화로 진입. (Expo Go 제약으로 dev 빌드 필요 → 별도 스프린트)
