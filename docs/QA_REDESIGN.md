# QA & 재설계 — 대화형 추천의 사용성 개선

작성 계기: "UX만 있고 실제 서비스처럼 안 굴러간다 / 광고가 미리 떠 있다 / LLM이 판단해서
필요할 때만 포인트로 연결해야 한다 / UI·UX를 최신 동향으로."

## 1. QA — 무엇이 문제였나

| # | 문제 | 원인 | 개선 |
|---|------|------|------|
| 1 | 광고가 **매 답변마다** 떠 있음("미리떠있어") | `matchForChat()`이 질문 종류와 무관하게 항상 혜택 2 + 미션 2 반환 | **니즈 게이팅**: 니즈가 없으면(none) 카드 미노출 |
| 2 | 의도 판단이 정규식뿐, 맥락 이해 없음 | 카테고리만 키워드로 추정 | LLM이 **need_level(none/exploring/ready)** 판정 |
| 3 | 추천이 **정해진 DB 랭킹 프레임** | `selectOfferForAnswer`가 순가치 정렬만 | **2단계 LLM 큐레이터**가 후보 중 판단·선별·이유 작성 |
| 4 | 폰에서 전부 목업(가짜 답변) | 백엔드 미연결 시 데모 모드 | 실제 LLM 연결 경로 명시(§4) + 목업도 게이팅 재현 |
| 5 | 포인트 연결이 약함 | 보상이 카드 내부에 묻힘 | **포인트(P) 앞세움** — 제안·카드·지갑 |
| 6 | 걷기·미션이 대화와 단절 | 별도 탭에만 존재 | 맥락 맞을 때 **reward_nudge**로 걷기/미션 연결 |

## 2. 핵심 컨셉 — "필요할 때만, 포인트로 연결"

대화 턴마다 답변을 **먼저 확정**한 뒤(Answer-First 불변조건 유지), LLM이 니즈 강도를 판정한다.

| need_level | 의미 | 화면 |
|---|---|---|
| **none** | 정보·잡담·감정 (상업 니즈 없음) | 답변만. "필요한 순간에만 연결" 안내 |
| **exploring** | 불편·관심이 드러남 | 답변 + **부드러운 제안 pill**(탭하면 카드 펼침) |
| **ready** | 지금 사려·신청하려 함 | 답변 + **전체 혜택 카드**(+필요시 미션) |

여기에 대화 맥락이 건강·산책·절약이면 `reward_nudge: walk`, 짧은 미션이 자연스러우면 `mission` —
걷기·광고 상호작용을 AI 대화 안으로 끌어온다.

## 3. 아키텍처 — 2단계 LLM (Answer-First 유지)

```
사용자 질문
  │
  ▼  [1단계] 답변 LLM  (provider.generateAnswer)   ← 오퍼 정보 절대 미전달
  │     └ 답변 + need_level + reward_nudge + need_summary(중립 요약)
  ▼  답변 확정(finalized_at 기록·해시)              ← 이 시점 이전 오퍼 조회 없음
  │
  ├─ need_level == none → 추천 안 함
  │
  ▼  [2단계] 추천 큐레이터 LLM  (provider.selectRecommendations)
        입력: need_summary + 검수된 후보 풀(수수료 정보 없음, commercial.chatCandidateBriefs)
        판단: 이 사람에게 정말 맞는 것만 0~2개 선별 + 맞춤 이유 작성
        복원: commercial.cardsFromPicks → 실제 카드(이유는 LLM 문장)
```

- 1단계는 광고를 모르므로 답변이 상업 논리에 오염되지 않는다(불변조건).
- 2단계는 **답변 확정 후**에만, 수수료가 아닌 **사용자 이득** 기준으로 판단한다.
- 키가 없으면 두 단계 모두 결정형 목업으로 폴백(키 없이도 데모 동작).

## 4. 실제 LLM로 구동하기 (가장 저렴 = Claude Haiku 4.5)

1. 루트에 `.env` 생성: `ANTHROPIC_API_KEY=sk-ant-...` (기본 등급 `AI_MODEL_TIER=fast` = Haiku 4.5, $1/$5 per 1M)
2. 백엔드 실행: `npm run dev` (http://localhost:3000)
3. **폰에서 실서버 답변**을 받으려면 앱이 PC를 향하게:
   `EXPO_PUBLIC_API_URL=http://<맥의_LAN_IP>:3000 npx expo start`
   (미설정 시 폰은 서버를 못 찾아 데모 목업으로 동작)

## 5. UI/UX 리프레시

- 채팅: 위→아래 시간순, 입력창 하단 고정, 첫 메시지에서 홈 숨김.
- 인터랙션: 타이핑 점 애니메이션, exploring 제안 **탭 확장**, 넛지 탭 → 걷기/미션 이동, 원형 ↑ 전송.
- 포인트 앞세움: 제안·카드·지갑에 P 강조. 광고 라벨·자동결제·연락처 전달은 솔직히 표기(다크패턴 금지).

## 6. 향후

- need_level·reward_nudge·큐레이션 이유의 실사용 로그 → 오탐(광고 과다/과소) 튜닝.
- 음성 입력(STT) 실제 연결(현재 입력창 포커스로 대체).
- 큐레이터에 사용자 이력(관심 카테고리·이전 클릭) 문맥 추가(동의 범위 내).
